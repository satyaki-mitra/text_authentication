# API Documentation - User Management Endpoint

## 1. Description

This document outlines the specifications for our RESTful API's User Management endpoint. The endpoint allows for creation, retrieval, updating, and deletion of user records within the system.

## 2. Endpoint

```
POST /api/users
GET /api/users/{userId}
PUT /api/users/{userId}
DELETE /api/users/{userId}
```

## 3. Authentication Requirements

All requests to this endpoint require an `Authorization` header with a valid JWT token. The token should be provided in the format:

```
Authorization: Bearer {your-token-here}
```

## 4. Request Parameters and Data Types

### POST /api/users

* **Content-Type:** `application/json`
* **Body:** A JSON object representing the new user to be created.

```json
{
    "firstName": "John",
    "lastName": "Doe",
    "email": "johndoe@example.com",
    "password": "securePassword123"
}
```

### GET /api/users/{userId}

* **Parameters:** `userId` - The unique identifier for the user to retrieve.
* **Response:** A JSON object representing the requested user.

```json
{
    "id": 1,
    "firstName": "John",
    "lastName": "Doe",
    "email": "johndoe@example.com"
}
```

### PUT /api/users/{userId}

* **Content-Type:** `application/json`
* **Parameters:** `userId` - The unique identifier for the user to update.
* **Body:** A JSON object containing the fields to be updated. If a field is not provided, it will retain its current value.

```json
{
    "firstName": "Jane",
    "lastName": "Doe"
}
```

### DELETE /api/users/{userId}

* **Parameters:** `userId` - The unique identifier for the user to delete.

## 5. Response Error Codes

* **401 Unauthorized**: The request is missing or contains an invalid JWT token.
* **403 Forbidden**: The provided JWT token does not have sufficient permissions to perform the requested action.
* **404 Not Found**: The specified user could not be found in the system.
* **500 Internal Server Error**: An unexpected error occurred while processing the request.
