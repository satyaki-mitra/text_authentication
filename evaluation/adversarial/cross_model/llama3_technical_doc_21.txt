**System Name:** Weather Alert System (WAS)

**Overview:**

The Weather Alert System (WAS) is a cloud-based API designed to provide real-time weather data and alert notifications to users. The system integrates with multiple weather forecasting services to deliver accurate and up-to-date information on various weather conditions, such as temperature, humidity, wind speed, and precipitation.

**Specifications:**

1. **API Endpoints:**
	* `/weather/current`: Returns the current weather conditions for a specified location (latitude and longitude).
	* `/weather/forecast`: Retrieves the 5-day forecast for a given location.
	* `/alerts`: Provides real-time alerts on severe weather events, such as tornadoes, hurricanes, or blizzards.
2. **API Request Parameters:**
	* `location`: A string containing the latitude and longitude coordinates (e.g., "37.7749, -122.4194").
	* `unit`: A string specifying the unit of measurement for temperature (Celsius or Fahrenheit).
3. **API Response Format:** JSON

**Usage Guidelines:**

1. **Authentication:** To access WAS, you must provide a valid API key in the `Authorization` header. You can obtain an API key by registering on our website.
2. **Rate Limiting:** To prevent abuse and ensure system stability, we enforce rate limits on API requests. The default limit is 100 requests per hour; however, this can be increased upon request for legitimate use cases.
3. **Error Handling:** WAS returns error responses in JSON format when an invalid or missing parameter is provided. Error codes are listed below:
	* `400`: Bad Request (invalid parameters)
	* `401`: Unauthorized (missing API key)
	* `429`: Too Many Requests (exceeding rate limits)
4. **Example Requests:**
	* `GET /weather/current?location=37.7749,-122.4194&unit=C`
	* `GET /weather/forecast?location=37.7749,-122.4194`
	* `GET /alerts?location=37.7749,-122.4194`

**Best Practices:**

1. Always provide a valid API key in the `Authorization` header.
2. Use the correct request parameters and format (JSON) to ensure accurate responses.
3. Respect rate limits to avoid account suspension or temporary blockage.
4. Handle error responses accordingly, as described in the documentation.

By following these guidelines and specifications, you can effectively integrate WAS into your applications and services, providing users with timely and accurate weather information.
