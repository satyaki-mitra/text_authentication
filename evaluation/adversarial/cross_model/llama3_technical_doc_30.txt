**API Documentation: Weather Forecast System**

**Overview**
The Weather Forecast System (WFS) is a RESTful API that provides access to current and historical weather data for locations worldwide. The system is designed to be scalable, reliable, and easy to use, making it an ideal solution for developers looking to integrate weather data into their applications.

**API Endpoints**

* **GET /weather/current**: Retrieves the current weather conditions for a given location (latitude, longitude, or city name).
	+ Parameters:
		- `lat` (required): Latitude of the location.
		- `lon` (required): Longitude of the location.
		- `city` (optional): City name (e.g., "New York").
	+ Response: A JSON object containing current weather conditions, including temperature, humidity, wind speed, and more.
* **GET /weather/history**: Retrieves historical weather data for a given location over a specified time period.
	+ Parameters:
		- `lat` (required): Latitude of the location.
		- `lon` (required): Longitude of the location.
		- `start_date` (optional): Start date of the time period in ISO format (e.g., "2022-01-01T00:00:00Z").
		- `end_date` (optional): End date of the time period in ISO format (e.g., "2022-01-31T23:59:59Z").
	+ Response: A JSON object containing historical weather data, including temperature, humidity, wind speed, and more.
* **GET /weather/forecast**: Retrieves a 5-day forecast for a given location.
	+ Parameters:
		- `lat` (required): Latitude of the location.
		- `lon` (required): Longitude of the location.
	+ Response: A JSON object containing a 5-day weather forecast, including temperature, humidity, wind speed, and more.

**API Request Headers**

* **Accept**: Specifies the desired response format (e.g., application/json).
* **Authorization**: Optional authentication token for API access control.

**API Response Format**
All API responses are formatted as JSON objects. For error responses, a JSON object with an `error` property is returned, containing an error message and HTTP status code.

**Error Handling**
The WFS API uses standard HTTP status codes to indicate errors. The following error codes are used:

* 400 Bad Request: Invalid input parameters.
* 404 Not Found: Location not found or data unavailable.
* 500 Internal Server Error: Unexpected system error.

**Usage Guidelines**

1. When making requests, use the `Accept` header to specify the desired response format (e.g., application/json).
2. For authentication, include an `Authorization` token in the request headers. If no token is provided, the API will return a 401 Unauthorized response.
3. Always validate and sanitize user input data before passing it to the WFS API.
4. Use the API's error handling mechanism to handle unexpected errors or exceptions.

**Technical Requirements**

* The WFS API supports HTTP/1.1 protocol and JSON (application/json) format.
* The system is designed to be scalable and reliable, with load balancing and caching mechanisms in place.
* For security purposes, all data transmitted between the client and server is encrypted using TLS 1.2 or higher.
