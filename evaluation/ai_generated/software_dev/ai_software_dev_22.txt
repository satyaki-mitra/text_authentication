Title: Documentation on Dependency Injection in Java Using Spring Framework

Introduction

Dependency Injection (DI) is a software design pattern that addresses the problem of managing dependencies between objects in a system. It's an essential principle in developing maintainable, testable, and scalable applications. This documentation explains the implementation of Dependency Injection in Java using the Spring Framework.

Spring Framework

Spring is a popular open-source Java framework that provides a comprehensive solution for building modern enterprise applications. It offers features like DI, aspect-oriented programming, data access, and web application development.

Dependency Inversion Principle (DIP)

To understand Dependency Injection, we need to first understand the Dependency Inversion Principle (DIP), one of the five SOLID principles. DIP states that high-level modules should not depend on low-level modules; both should depend on abstractions. This separation allows for easier testing, maintenance, and scalability of our codebase.

Implementing Dependency Injection in Spring

In Spring, DI is achieved through the Configuration classes (such as XML configurations or annotations like @Configuration). We can define our beans (objects) and their dependencies within these configuration files. Spring's DI container then manages the life cycle of these beans and injects them into other beans when required.

Here's a simple example demonstrating DI in Spring:

```java
// Service interface
public interface MessageService {
    void sendMessage(String message);
}

// Concrete implementation of the service
@Component
public class EmailMessageService implements MessageService {
    @Override
    public void sendMessage(String message) {
        // Sending email with the provided message
    }
}

// Configuration class
@Configuration
public class AppConfig {

    @Bean
    public MessageService messageService() {
        return new EmailMessageService();
    }
}
```

In this example, we define an interface `MessageService` and its concrete implementation `EmailMessageService`. In our configuration class `AppConfig`, we create a bean for the `MessageService` instance using the `@Bean` annotation. Spring will manage the lifecycle of this bean and inject it wherever required through constructor injection (in this case) or setter injection.

```java
// Controller using MessageService
@Controller
public class ExampleController {
    private final MessageService messageService;

    public ExampleController(MessageService messageService) {
        this.messageService = messageService;
    }

    @RequestMapping("/example")
    public String handleRequest() {
        messageService.sendMessage("Hello World!");
        return "example";
    }
