Title: API Documentation - User Management Endpoint

## User Management API

### Endpoint Description

This REST API provides endpoints for managing users within our system. The `/users` endpoint is used to create, retrieve, update, and delete user records.

### Request Parameters

| Parameter          | Data Type   | Required | Description                                                                                                       |
|--------------------|------------|----------|-------------------------------------------------------------------------------------------------------------------|
| `action`           | `string`   | Yes      | Action to perform on the user: `create`, `read`, `update`, or `delete`.                                         |
| `id`               | `integer`  | Optional | Unique identifier of the user (for `update` and `delete` actions).                                              |
| `username`         | `string`   | Yes (for `create`) / Optional (for `update`) | The username for the user.                                                                                          |
| `password`         | `string`   | Yes (for `create`) / Optional (for `update`) | The password for the user. (Note: Passwords are hashed and not stored in plaintext.)                             |
| `email`            | `string`   | Yes      | The email address of the user.                                                                                    |
| `first_name`       | `string`   | Optional | The first name of the user.                                                                                     |
| `last_name`        | `string`   | Optional | The last name of the user.                                                                                      |
| `roles`            | `array`    | Optional | An array of roles assigned to the user. (e.g., ["admin", "user"])                                              |

### Authentication Requirements

All requests require authentication using API keys. The API key should be included in the request header with the key `Authorization`.

Example:
```bash
Authorization: Bearer <your_api_key>
```

### Example Requests

#### Create a new user

```bash
POST /users
Content-Type: application/json

{
  "action": "create",
  "username": "john_doe",
  "password": "secret123",
  "email": "john.doe@example.com",
  "first_name": "John",
  "last_name": "Doe",
  "roles": ["user"]
}
```

#### Retrieve user details

```bash
GET /users/<id>
Authorization: Bearer <your_api_key>
