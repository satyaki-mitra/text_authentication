**API Documentation - User Management System**

**Endpoint:** `POST /api/v1/users`

**Description:** This API is used to create a new user in the system. The endpoint accepts JSON data containing user details.

**Authentication Requirements:** All requests to this endpoint require an access token for authentication. The token should be included in the `Authorization` header with format: `Bearer {access_token}`.

**Request Parameters:**

- `name` *(string, required)*: The full name of the user (First Name Last Name).
- `email` *(string, required, unique)*: A unique email address for the user.
- `password` *(string, required)*: The password for the user.
- `role` _(enum: 'admin', 'user', default: 'user')_: The role of the user in the system (admin or user).

**Example Request:**

```bash
POST /api/v1/users HTTP/1.1
Host: yourdomain.com
Authorization: Bearer {access_token}
Content-Type: application/json

{
  "name": "John Doe",
  "email": "johndoe@example.com",
  "password": "securepassword123",
  "role": "admin"
}
```

**Response Parameters:**

- `id` *(integer, read-only)*: The unique identifier for the user.
- `name` *(string)*: The full name of the user.
- `email` _(string)_: The email address of the user.
- `role` _(enum: 'admin', 'user')_: The role of the user in the system.

**Example Response:**

```json
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": 1,
  "name": "John Doe",
  "email": "johndoe@example.com",
  "role": "admin"
}
```

**Error Codes:**

- `401 Unauthorized`: Invalid or missing access token.
- `422 Unprocessable Entity`: Invalid input data provided.
- `409 Conflict`: The email address is already in use.

**Usage Notes:**

- Always ensure to send the access token for authentication.
- Password should be hashed before sending and stored securely in the database.
- Use appropriate error handling when receiving error responses from this endpoint.
