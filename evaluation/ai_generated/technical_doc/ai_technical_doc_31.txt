Title: API Documentation - User Management Endpoint

## User Management Endpoint

The `User Management` endpoint provides a RESTful interface for creating, retrieving, updating, and deleting user accounts in the system. This documentation outlines the specifics of the endpoint, its parameters, authentication requirements, example requests, error codes, and usage notes.

### Endpoint Description

- **Endpoint URL:** `https://api.example.com/v1/users`
- **HTTP Method:** `GET`, `POST`, `PUT`, `DELETE`
- **Rate Limit:** 60 requests per minute
- **Authentication Required:** Yes (JWT Access Token)

### Request Parameters

#### GET /users

- **Parameters:** None
- **Response Format:** JSON

#### POST /users

- **Request Body (JSON):**
```json
{
  "username": "string",
  "email": "string",
  "password": "string"
}
```

#### PUT /users/{id}

- **Parameters:**
	+ `id`: Required, unique user identifier (integer)
- **Request Body (JSON):**
```json
{
  "username": "string",
  "email": "string"
}
```

#### DELETE /users/{id}

- **Parameters:**
	+ `id`: Required, unique user identifier (integer)

### Response Parameters

- **Response Format:** JSON
- **Status Code:**
    + 200 OK: Success
    + 400 Bad Request: Invalid request data
    + 401 Unauthorized: Missing or invalid access token
    + 403 Forbidden: Insufficient permissions
    + 404 Not Found: User not found
    + 500 Internal Server Error: Unexpected error occurred

#### Example Responses

- **Success Response (200 OK):**
```json
{
  "id": 1,
  "username": "exampleUser",
  "email": "example@example.com"
}
```

- **Error Response (401 Unauthorized):**
```json
{
  "error": "Unauthorized"
}
```

### Usage Notes

1. All requests must include a valid JWT access token in the `Authorization` header with format: `Bearer {access_token}`
2. When creating new users, ensure that the provided email and username are unique within the system.
3. Users can only update their own account information using the PUT endpoint.
4. The DELETE endpoint will permanently delete
