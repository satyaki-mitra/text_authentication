Title: API Documentation - User Management Endpoint

## User Management Endpoint

### Description

This endpoint provides a RESTful interface for managing user accounts within the system. It allows for creation, retrieval, updates, and deletion of user data.

### Endpoint URL

`https://api.example.com/v1/users`

### Authentication Requirements

All requests to this endpoint require authentication using JSON Web Tokens (JWT). The `Authorization` header must contain a valid JWT token for authentication.

Example:
```
Authorization: Bearer {your_token_here}
```

### Request Parameters

#### Create User (POST)

- **Content-Type:** `application/json`

```json
{
  "username": "<string>",
  "email": "<email>",
  "password": "<string>",
  "role": "<role_name>"
}
```

#### Retrieve User (GET)

- **URL Parameters:** `id` - Required, integer user ID

Example:
`https://api.example.com/v1/users/123`

#### Update User (PUT)

- **Content-Type:** `application/json`

```json
{
  "username": "<string>",
  "email": "<email>",
  "password": "<string>",
  "role": "<role_name>"
}
```

- **URL Parameters:** `id` - Required, integer user ID

#### Delete User (DELETE)

- **URL Parameters:** `id` - Required, integer user ID

### Response Parameters

#### Successful Responses (2xx)

A successful response will contain a JSON object with the requested data or an empty body for DELETE requests.

Example:
```json
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 123,
  "username": "john_doe",
  "email": "john.doe@example.com",
  "role": "admin"
}
```

#### Error Responses (4xx/5xx)

Error responses will contain a JSON object with an error message and appropriate HTTP status code.

Example:
```json
HTTP/1.1 401 Unauthorized
Content-Type: application/json

{
  "error": "Invalid or missing token"
}
```
